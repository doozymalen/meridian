# Meridian — 파노라마 이미지 스티칭

PTGui 처럼 여러 장의 사진을 하나의 파노라마로 잇는 macOS 앱이다.

화면은 AppKit 으로 만든 네이티브 앱이다. 정렬과 합성은 파이썬(OpenCV·SciPy)이
맡는데, 그 엔진은 앱이 번들 안에서 자식 프로세스로 띄우고 임의 포트로만
대화한다. 브라우저는 열리지 않고, 앱이 끝나면 엔진도 같이 정리된다.
원본 사진은 언제나 있던 자리에서 읽는다.

## 실행

```bash
./build_app.sh        # dist/Meridian.app (약 360MB, 파이썬 런타임 포함)
open dist/Meridian.app
```

만들어진 `.app` 은 자립적이라 파이썬이 없는 맥에 복사해도 그대로 돈다.
코드만 고쳤으면 `./build_app.sh --code-only` 가 몇 초 만에 끝난다.

엔진만 따로 띄워 브라우저에서 쓰고 싶으면 `./run.sh` 를 쓰면 된다.

## 화면

세 칸으로 나뉜 창 하나다.

- **왼쪽** — 사진 목록. 파일 이름과 화소 수, RAW 여부, 기준 사진 표시.
  오른쪽 눌러 빼거나 기준으로 바꿀 수 있다.
- **가운데** — 파노라마 미리보기와 제어점 편집기. 툴바 가운데(또는 ⌘1 / ⌘2)로 오간다.
- **오른쪽** — 투영과 합성, 렌즈 정보, 출력 크기. 작업 내내 보면서 쓰는 곳이라
  접히지 않는다.

사진은 **창 어디에나 끌어다 놓으면** 된다. 폴더를 놓으면 그 안의 사진을 훑는다.

### 제어점 편집기

자동 정렬이 어긋난 자리를 직접 이어 주는 곳이다.

- 왼쪽 사진을 클릭하면 오른쪽에서 짝을 찾아 준다. 자신 없으면(일치도 0.45 미만)
  예측 위치로 화면만 옮겨 주고 사람이 찍게 둔다
- ⌥클릭으로 양쪽을 직접 지정, 점을 고른 뒤 ⌫ 로 삭제
- 커서 밑을 6배로 비추는 **확대경** — 한 화소를 다투는 작업이라 이게 없으면
  정확히 찍을 수가 없다
- 마커 색이 곧 잔차다: 청록(양호) · 주황(5px 초과) · 빨강(12px 초과)
- 수직선·수평선 제어점으로 건축 사진의 기울기를 잡는다

툴바에서 사진 추가 · 자동 정렬 · 최적화 · 수평 맞추기를 한다.
사이드바는 ⌘S 로 접을 수 있고, 창 크기와 칸 너비는 다음에도 그대로 열린다.

## 쓰는 순서

1. **사진 추가** — macOS 파일 선택창이 열린다. 폴더째 넣어도 된다.
   창으로 끌어다 놓아도 되지만, 수 GB 짜리 RAW 는 파일 선택창 쪽이 빠르다.
2. **자동 정렬** — 특징점을 찾아 제어점을 만들고, 카메라 자세·화각·렌즈 왜곡을
   한꺼번에 푼다. 끝나면 렌즈 비네팅도 잰다.
3. 결과가 어긋나면 **제어점** 탭에서 손으로 점을 찍거나 나쁜 점을 끈다.
4. **내보내기** — 원본 해상도로 렌더해 바탕화면에 저장한다.

## 기능

**입력**
- JPEG / TIFF / PNG 와 카메라 RAW (`.ARW .CR2 .CR3 .NEF .DNG .RAF .ORF .RW2 …`)
- EXIF 에서 렌즈 이름, 초점거리, 35mm 환산값을 읽어 화각을 추정한다
- 같은 렌즈로 찍은 사진은 자동으로 묶어 파라미터를 공유한다

**정렬**
- SIFT(RootSIFT) 특징점 + 전역 FLANN 인덱스로 겹치는 쌍을 찾는다.
  이미지 수가 아니라 특징점 수에 비례하므로 수백 장도 감당한다
- 번들 조정으로 모든 카메라의 yaw/pitch/roll, 화각, 방사 왜곡(a·b·c),
  주점 이동을 동시에 푼다
- 제어점을 직접 찍을 수 있고, 한쪽을 클릭하면 반대쪽 짝을 찾아 준다
- 수직선·수평선 제어점으로 건축 사진의 기울기를 잡는다

**투영**
구면(equirectangular) · 원통 · 직선 · 메르카토르 · 스테레오 · 어안,
그리고 **리틀 플래닛** / **터널** 프리셋.

**합성** (보정은 모두 꺼진 채로 시작한다 — 필요한 것만 눈으로 보며 켠다)
- 비네팅·미광 보정 — 겹침에서 `관측 = 실제밝기 × V(r) × 노출 + 미광` 을 푼다.
  `V(r) = 1 + a·r² + b·r⁴ + c·r⁶`. 미광(렌즈 내부 산란광)은 더해지는 성분이라
  배율만으로는 절대 맞출 수 없다. 곡선에는 단조 감소·매끄러움 제약을 건다
- 노출·화이트밸런스 맞춤 (이미지별 게인)
- 밝기 기울기 맞춤 — 이미지 *안에서* 완만하게 변하는 차이를 서로 맞춘다.
  하늘처럼 매끄러운 면에 생기는 쐐기 모양 얼룩을 없애는 것이 이 단계다
- 이음선 찾기 — 먼저 **거리 변환으로 크게 나누고** 그 다음 다듬는다.
  천정처럼 모든 사진의 가장자리가 모이는 곳에서 쌍끼리 이음선을 찾으면 경계가
  잘게 쪼개지고, 구름처럼 장마다 모습이 다른 대상이 조각조각 맞붙어 원호 모양
  경계로 드러난다. 거리 분할은 한 사진이 넓은 면을 통째로 맡게 해서 그 문제를
  없앤다 (PTGui 의 ApplySeamFinderToDistanceMap 과 같은 발상)
- 멀티밴드 블렌딩

**출력**
- 가로 픽셀을 직접 지정하거나 배율(5~400%)로. 상한은 없다
- JPEG / TIFF(LZW) / PNG(투명 포함)
- 기가픽셀 출력은 타일 스트리밍으로 렌더한다. 캔버스는 디스크에 memmap 으로
  잡으므로 16GB 맥에서도 수십억 화소를 낼 수 있다

## 구조

```
meridian/
  camera.py       카메라·렌즈 모델, 투영 수학 (픽셀 ↔ 광선 ↔ 파노라마)
  images.py       RAW 디코딩, EXIF, 프록시 캐시
  features.py     SIFT 검출·매칭, 자동 제어점
  optimize.py     번들 조정, 초기값 추정, 수평 맞추기
  photometric.py  비네팅·노출 추정
  warp.py         캔버스 배치와 워핑
  blend.py        노출 보정, 밝기 기울기 맞춤, 이음선, 블렌딩
  render.py       미리보기와 타일 스트리밍 최종 렌더
  project.py      프로젝트 상태와 저장
  server.py       로컬 웹 서버
web/              브라우저 UI (바닐라 JS, 프레임워크 없음)
```

좌표 규약과 왜곡 모델의 방향 같은 전제는 각 모듈 맨 위 주석에 적어 두었다.

## 알아 둘 것

- 노달 포인트를 맞추지 않고 찍으면 가까운 물체에서 시차가 생긴다.
  스티칭으로는 지울 수 없으니 촬영 때 잡아야 한다.
- 구름이 움직이거나 사람이 지나간 자리는 이음선이 그 위를 지나가지 않도록
  이음선 방식을 바꿔 보는 편이 낫다. 하늘이 지저분하면 '거리 분할만' 을
  골라 한 사진이 더 넓은 면을 맡게 하면 대개 정리된다.
- OpenCV 5 의 `VoronoiSeamFinder` 와 `NoSeamFinder` 는 Python 바인딩에서
  세그폴트가 난다. 그래서 목록에 두지 않았다.

## 윈도우

엔진(정렬·합성)은 플랫폼을 가리지 않는다. OpenCV·SciPy·rawpy 모두 윈도우 휠이 있고,
운영체제에 기대는 부분(파일 선택창, 탐색기 열기, 부모 프로세스 감시)은 분기해 두었다.

화면은 다르다. 맥 쪽 창은 AppKit 으로 만든 것이라 윈도우에서 쓸 수 없다.
그래서 윈도우에서는 같은 엔진 위에 웹 UI(`web/`)를 얹고, 브라우저를 주소창 없는
'앱 창' 모드로 띄운다(Edge 나 Chrome 이 있으면 자동으로 찾는다).

**빌드는 윈도우 PC 에서 해야 한다.** 파이썬 실행 파일은 교차 빌드가 되지 않아
맥에서 `.exe` 를 만들 수 없다. 소스를 옮긴 뒤 PowerShell 에서:

```powershell
.\windows\build_windows.ps1
```

`dist\Meridian\Meridian.exe` 가 나온다. 폴더째 옮기면 파이썬이 없는 PC 에서도 실행된다.

## 파노라마 방향

속성 패널의 **파노라마 방향**에서 좌우(yaw)·상하(pitch)·기울기(roll)를 각도로 넣고
적용한다. 수평이 틀어졌으면 툴바의 **수평**이 자동으로 잡아 주고, 미세 조정은 roll 로 한다.

## 배치 확인

화면을 직접 볼 수 없는 자리에서 레이아웃을 점검할 때:

```bash
MERIDIAN_DUMP_LAYOUT=1 ./dist/Meridian.app/Contents/MacOS/Meridian
```

창과 세 칸, 속성 패널 안쪽, 제어점 편집기의 실제 크기와 확대 비율을 찍는다.
창이 멀쩡히 떠 있는데 내용만 비는 종류의 문제는 이걸 봐야 알 수 있다.

곁들여 쓸 수 있는 것들:

```bash
MERIDIAN_TRACE=1           # 사진을 물리고 그리는 호출을 따라간다
MERIDIAN_START_MODE=cp     # 제어점 탭으로 바로 연다
MERIDIAN_PROJECT=<절대경로> # 저장해 둔 프로젝트를 열고 시작한다
```

## 요구 사항

**macOS 11 (Big Sur) 이상, Apple Silicon.**

UI 코드 자체는 macOS 10.15 에서도 컴파일되도록 맞춰 두었지만(`mac/Sources/Compat.swift`),
실제 배포 하한은 11.0 이다. Apple Silicon 맥의 최소 OS 가 11.0 이라 그 아래로 내려갈
이유가 없기 때문이다.

Intel 맥까지 담은 universal 바이너리는 x86_64 용 Swift 호환성 라이브러리가 필요한데,
Command Line Tools 에는 arm64 슬라이스만 들어 있어 빌드되지 않는다. Xcode 가 설치된
환경이라면 `MERIDIAN_UNIVERSAL=1 ./build_app.sh` 로 시도할 수 있다. 다만 파이썬 런타임도
x86_64 용을 따로 담아야 해서 번들 크기가 두 배가 된다.

개발용으로 돌리려면 [uv](https://docs.astral.sh/uv/) 가 필요하다.
